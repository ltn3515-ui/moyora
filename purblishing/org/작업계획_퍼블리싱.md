# '모여라' 앱 퍼블리싱 작업계획서 (통합본 v3)

## 0. 개요
- 프로젝트명: 모여라 (모임과 정산을 한번에!)
- 목표: 기존 9개 화면(스플래시/메인/친구/내정보/나의모임/검색/정산관리/신규생성/영수증QR카메라) + 신규 3개 화면(환경설정/대표계좌관리/저장된순간들) = **총 12개 화면**을 HTML/CSS/JS(Vanilla)로 퍼블리싱
- 방식: SPA(페이지 이동 없음, JS로 화면/모달 전환)
- 향후: React 전환 예정 → 데이터 구조를 명확한 객체/배열로 설계
- 진행 현황: `friends.html`(친구), `profile.html`(내 정보), `search.html`(검색 모달), `camera.html`(영수증 QR 카메라 모달) 작업 완료 ✅ / 나머지 8개 화면 예정

> 화면 간 관계: splash → index(메인 허브) → 하단 네비게이션으로 friends / add(나의 모임) / profile 이동. search는 friends.html(및 필요 시 index.html)의 검색창에서 호출되는 오버레이 모달로 동작.
> **기존 신규 화면 관계**: calculate.html은 add.html(나의 모임)에서 특정 모임을 선택했을 때 진입하는 정산 상세/대시보드 화면, newcru.html은 add.html의 "새 모임 만들기" 진입점을 대체하는 멀티스텝 생성 플로우, camera.html은 calculate.html의 "QR 카메라" 버튼에서 호출되는 오버레이 모달로 가정.
> **이번 신규 화면 관계**: profile.html의 메뉴 리스트 중 "계정설정" → **option.html**로 이동, "저장된 순간들" → **memory.html** 모달 오픈. option.html의 "대표 계좌 관리" 항목 → **account.html**로 이동. (option.html의 "프로필 설정"/"비밀번호 변경", "서비스 이용약관 및 정책"은 이번 시안에 없어 이동 없이 자리만 잡아두고, 추후 시안 주시면 연결)

## 2. 디자인 톤 & 공통 스타일 방향

- 컬러 시스템 (기존 `common.css` 토큰 그대로 유지)
  - Primary Yellow: `--color-yellow: #FEDD13` / Primary Pink: `--color-pink: #F491BC`
  - Sub Blue / Green / Cream / Gray: 보조 파스텔
  - 텍스트: `--color-text`(본문), `--color-text-sub`(보조 텍스트)
  - 배경: `--color-bg`(아이보리/오프화이트 톤), 카드 배경 `--color-bg-card`
  - 신규 포인트: option.html 프로필 카드는 옐로우 배경(기존 friends.html 프로필 카드와 톤 통일), account.html 안내 카드는 핑크 글로우 강조, memory.html 필터 탭/이미지 카드는 옐로우·핑크·블루·크림 파스텔을 교차 배치
- 타이포그래피/레이아웃/리셋: 기존 common.css 스케일과 `max-width: 480px` 그대로 유지
- 공통 컴포넌트 재사용: 카드(.card), 버튼(.btn/.btn-primary/.btn-floating), 하단 네비게이션(.bottom-nav), 아바타(.avatar), 헤더(.app-header), 뱃지(.badge)
- 신규 화면에서 추가로 필요한 공통 패턴(common.css에 추가 검토):
  - 리스트형 메뉴 아이템(아이콘 + 라벨/서브텍스트 + 화살표 또는 토글/드롭다운) — option.html
  - 토글 스위치(on/off) — option.html 알림 설정
  - 폼 입력 필드(라벨 + input + 보조 버튼) — account.html
  - 필터 탭(pill, 색상별 활성 상태) — memory.html (search.html 인기 카테고리와는 별개 패턴)
  - 2열 이미지 카드 그리드(사진 + 하단 메타정보 오버레이) — memory.html
- 스타일 원칙: 미니멀, 카드 기반 UI, 모바일 우선

## 5. 작업 순서

### 5-1~5-3 (기존, 완료됨)
1. 공통 스타일/데이터 정의, calculate/newcru/camera 순서로 진행 예정이었으나, 실제로는 요청 순서에 따라 **friends.html → common 통합 → profile.html → common 통합 → camera.html** 순으로 완료됨

### 5-4. 신규 3개 화면 (이번 요청 우선순위)
1. **공통 스타일 보강** — `common.css`에 리스트형 메뉴 아이템, 토글 스위치, 폼 입력 필드, 필터 탭, 2열 이미지 카드 그리드 패턴 추가
2. **data.js 확장** — `appSettings`, `payoutAccount`, `bankOptions`, `savedMoments` 및 관련 함수 추가
3. **환경 설정 화면(option.html)** — 프로필 카드 + 메뉴 리스트 + 알림 토글 + 다국어 드롭다운
4. **대표 계좌 관리 화면(account.html)** — 안내 카드 + 계좌 등록 폼
5. **저장된 순간들 모달(memory.html)** — 필터 탭 + 2열 이미지 그리드

### 5-5. 잔여 화면 (신규 3개 완료 후 이어서 진행 제안)
6. 정산 관리 화면(calculate.html) / 신규 생성 화면(newcru.html)
7. 스플래시 화면(splash.html) / 메인 화면(index.html)
8. 나의 모임 화면(add.html)

> 화면별로 순서대로 요청하실 예정이라, 위 순서는 제안이며 실제 작업은 요청하시는 순서를 따릅니다.

## 6. 확인 요청 사항

1. **화면 관계 가정 확인**: 1번 항목 하단에 적은 대로 profile.html ↔ option.html ↔ account.html, profile.html ↔ memory.html 관계로 이해하고 진행해도 될지 확인 부탁드립니다.
2. **option.html의 미시안 항목**: "프로필 설정", "비밀번호 변경", "서비스 이용약관 및 정책" 항목은 이번 시안에 상세 화면이 없어 우선 리스트 자리만 만들고 클릭 시 동작은 다음 단계로 남겨두는 것으로 진행해도 될지 확인 부탁드립니다.
3. **account.html 저장 동작**: "저장하기" 클릭 시 별도 확인 모달 없이 `payoutAccount` 값을 바로 갱신하고 이전 화면(option.html)으로 돌아가는 흐름으로 가정했는데 괜찮을지 확인 부탁드립니다.
4. 위 계획대로 진행해도 괜찮으시면, 요청하신 순서(공통 스타일 보강 → option.html → account.html → memory.html)로 다음 메시지부터 화면별로 작업 시작하겠습니다.
